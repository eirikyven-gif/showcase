## Inspected source and route mapping

Source repository: `eirikyven-gif/lagerstyring-hell-ultra`, commit `f1f13246677d15de24e84070d8dad74f2a0376ee` (read-only). Showcase route: `/vibe/lagerstyring-hell-ultra/`; proposed version `0.61.0`, based on current main `0.60.1`. No fixed portal slug exists in source. The CPT rewrite is `/lager-enhet/{post-slug}` (`includes/class-hul-lager-cpt.php:50`), with item magic-link route `/hul-lager/item/{32-char-token}` and list route `/hul-lager/liste/{32-char-token}` (`includes/class-hul-lager-magic-link.php`). Showcase maps them to `#/`, `#/item/{synthetic-id}`, `#/list/{local-list-id}`. These are route equivalents; no token/auth semantics are reproduced.

`lagerkart-vinter` is a separate vehicle storage position map and has no portal, item detail, loan, or shared-list workflow overlap.

## Allowed substitutions and risk boundaries

WordPress auth/capabilities/nonces, server/database persistence, opaque magic-link secrets, real contact/person data, private media/services, external APIs and secrets remain removed. UI roles are explicitly illustrative, never authorization. State and selected files stay in the browser session and are cleared on reload. All sample identities, values and fixtures are synthetic; no source-private data/media is reused. Local list IDs are not access credentials.
