## Security substitutions allowed

Real WordPress authentication/capability checks, nonces, database/server persistence, opaque authorization tokens, real borrower/person data, private media, remote APIs/services and secrets stay removed. Their user-visible workflow can be simulated in memory using synthetic content. Browser persistence is not needed; refresh resets state. Demo roles are illustrative only, never actual access control. Do not add unrelated controls or workflow behavior absent from the source.

## Existing demo-specific behavior to review

The previous implementation adds a role picker and a status edit directly on item detail. The source does have WordPress manager capabilities and status editing in the inventory editor, but it does not expose that editor from the public magic-link page. Move the status edit to the simulated admin inventory editor and remove the manager mutation from public item detail.

## Current conclusion

The merged demo is not functionally source-faithful while any matrix gaps remain. This audit does not claim completion. Keep the corrective PR draft until every source workflow and content surface above is implemented and exercised, or the remaining blocker is plainly identified and the PR is left unready.
